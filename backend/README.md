# PostureGuard study server

Receives finished sessions from the app and stores them for analysis. The
request format is [`study/API_SCHEMA.md`](../study/API_SCHEMA.md).

FastAPI + SQLAlchemy. PostgreSQL in deployment, SQLite for local development
and tests.

| Endpoint | What it does |
|---|---|
| `POST /api/sessions` | Stores one session: summary, per-second events, device metrics |
| `GET /health` | Returns `{"ok": true}` |

## Run locally

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --reload
```

The server listens on `http://127.0.0.1:8000` and writes to
`backend/postureguard.db` (SQLite). Set `DATABASE_URL` to use PostgreSQL
instead. Tables are created on startup if missing; existing tables are never
altered.

To point a phone at it during development, build the app with
`--dart-define=API_BASE_URL=http://<this computer's LAN IP>:8000` and run
uvicorn with `--host 0.0.0.0`. Android blocks plain HTTP by default, so this
needs a debug network exception or, better, the HTTPS setup below.

## Tests

```bash
cd backend
.venv/bin/python -m pytest
```

The payloads in `tests/fixtures/` were generated by the app's own
`buildSessionPayload` and integrity check, so the tests check the server
against what the phone really sends. Regenerate them when the payload changes.

## Run with Docker

```bash
cd backend
echo "POSTGRES_PASSWORD=change-me" > .env
docker compose up -d --build
```

Starts PostgreSQL and the API on `127.0.0.1:8000`. HTTPS (Nginx in front of
the API) is the next step and not set up yet.

## What the server accepts

| Case | Response |
|---|---|
| Clean session (`integrity.is_valid: true`) | `200 {"ok": true}` |
| Gap-only session (`is_valid: false`, `gap_count > 0`) | `200 {"ok": true}`, stored with `is_valid = false` |
| Same `(user_id, session_id)` again — a retry | `200 {"ok": true, "duplicate": true}`, first copy kept |
| Bad `user_id` (not 6–20 letters/numbers) or `variant` (not A, B or C) | `422` |
| Events not in strictly increasing time order | `422` |
| `is_valid: false` with `gap_count: 0`, or `missing_count > 0` | `422` — only gap-only sessions may be uploaded as invalid |
| No events | `422` |

`variant` `C` is accepted so internal test sessions can be uploaded; it is
hidden from participants and excluded from analysis.

Sessions are keyed by `(user_id, session_id)`: `session_id` is the session's
start time and only unique per phone.

## Tables

`sessions` (one row per session, device-metrics summary flattened in),
`posture_events` (one row per second), `device_metrics` (one row every 15 s).
No names or emails — those stay in the onboarding form's restricted linking
list.
